Ambiten v1.2.0: Strengere Schema-Durchsetzung und eine besser vorhersehbare Laufzeit

Ambiten entwickelt sich weiterhin auf der Grundlage einer einfachen Idee: Die Infrastruktur sollte die Anwendungsentwicklung vorhersehbarer machen, nicht komplizierter.

Verfasst von Emmanuel Abiodun Nodolomwanyi
Produkthinweis 23. August 2026 6 Minuten Lesezeit

Bei Ambiten v1.2.0 lag der Schwerpunkt auf der Stärkung einiger der Laufzeitbeziehungen, auf die Entwickler am meisten angewiesen sind: die Verbindung zwischen Schemata und Modellen, die Dokumentvalidierung sowie der Lebenszyklus einer initialisierten Ambiten-Laufzeitumgebung.

Diese Änderungen mögen für sich genommen geringfügig erscheinen, doch in ihrer Gesamtheit sorgen sie für eine größere Kohärenz der Laufzeitumgebung und bieten Entwicklern stärkere Garantien, wenn Anwendungen an Umfang zunehmen.

Von der Schema-Registrierung bis zur Schema-Durchsetzung

Ambiten hat schon immer Schema- und Modellabstraktionen bereitgestellt, doch in Version 1.2.0 wird die Verbindung zwischen diesen beiden Aspekten gestärkt.

Bei der Verwendung von AmbitenBootstrapFactory, kann ein Schema parallel zur Modellkonfiguration definiert werden: 

import {
  AmbitenBootstrapFactory
} from "@ambiten/core";

export async function run() {
  return AmbitenBootstrapFactory.create({
    config: {
      schema: {
        username: {
          type: "string",
          required: true,
          unique: true
        },
        password: {
          type: "string",
          required: true
        },
        email: {
          type: "string",
          required: true
        }
      },

      model: {
        collectionName: "users"
      }
    }
  });
}

Während des Bootstrap-Vorgangs erstellt Ambiten das Laufzeitschema und verknüpft es mit dem initialisierten Modell. Diese Verknüpfung wirkt sich nun direkt auf die Dokumentenoperationen aus.

Wenn ein Modell ein Dokument erstellt, wird das registrierte AmbitenSchema ist an der Validierung beteiligt, bevor das Dokument MongoDB erreicht. Dies bedeutet, dass ein Fehler wie beispielsweise: 

await userModel.create({
  usernmae: "john",
  password: "secret",
  email: "john@example.com"
});

kann abgelehnt werden, weil usernmae ist nicht Teil des registrierten Schemas. Anstatt zuzulassen, dass ein falsch strukturiertes Dokument unbemerkt in die Datenbank gelangt, kann Ambiten das Problem bereits vor der Speicherung aufdecken.

Verbesserte Vertragsdokumente

Das flexible Dokumentenmodell von MongoDB ist eine seiner Stärken, doch Flexibilität muss nicht zwangsläufig bedeuten, dass man auf Garantien auf Anwendungsebene verzichten muss.

Mit Version 1.2.0 kann die Schemaebene von Ambiten aktiver zur Durchsetzung dieser Garantien beitragen. Je nach Schemadefinition kann die Validierung nun unbekannte Dokumenteigenschaften, erforderliche Eigenschaften, erwartete Feldtypen sowie benutzerdefinierte synchrone oder asynchrone Validatoren berücksichtigen.

Beispiel:

const schema = runtime.getSchema();

schema.validator("username", (value) => {
  return value.length >= 3;
});

Benutzerdefinierte Validatoren stehen weiterhin zur Verfügung, ergänzen jedoch nun den durch das Schema beschriebenen Strukturvertrag, anstatt unabhängig davon zu funktionieren.

Der Ablauf zur Laufzeit wird deutlich übersichtlicher:

Schema Definition
      |
AmbitenSchema
      |
AmbitenModel
      |
Document Validation
      |
MongoDB

Das Modell kennt das Schema, zu dem es gehört, und das Schema spielt eine aktive Rolle bei der Feststellung, ob ein Dokument gültig ist.

Ein übersichtlicheres Bootstrap-Erlebnis

Eines der Ziele von AmbitenBootstrapFactory besteht darin, den Umfang der Infrastruktur-Verkabelung zu reduzieren, die der Anwendungscode manuell durchführen muss. Die Entwickler beschreiben die gewünschte Laufzeitumgebung: 

const runtime =
  await AmbitenBootstrapFactory.create({
    config: {
      schema: {
        username: {
          type: "string",
          required: true
        },
        email: {
          type: "string",
          required: true
        }
      },

      model: {
        collectionName: "users"
      }
    }
  });

Die initialisierten Ressourcen stehen dann über die Laufzeit zur Verfügung:

const userModel = runtime.getModel();
const userSchema = runtime.getSchema();

Der Anwendungscode muss keine wiederholte Verbindung zum Schema, zur Sammlung und zum Modell herstellen. Diese Aufgabe obliegt dem Bootstrap. Die Anwendung kann sich auf die Nutzung der initialisierten Laufzeitumgebung konzentrieren.

Vorhersehbarere Hooks für Laufzeitverbindungen

Ambiten v1.2.0 optimiert zudem den Lebenszyklus der Laufzeitverbindung. Anwendungen können eine onConnect Callback: 

runtime.onConnect(() => {
  console.log("Ambiten connected");
});

Das Verhalten ist so ausgelegt, dass es vorhersehbar ist. Wenn die Laufzeitumgebung noch auf ihre Verbindung wartet, kann der Callback ausgeführt werden, sobald die Laufzeitumgebung verbunden ist. Ist die Initialisierung bereits abgeschlossen, wenn der Callback registriert wird, kann Ambiten diesen sofort ausführen, anstatt die Anwendung auf ein Ereignis warten zu lassen, das bereits eingetreten ist.

Dadurch lassen sich Muster wie die folgenden problemlos umsetzen:

runtime.onConnect(() => {
  const client = runtime.getMongoClient();

  console.log(
    "MongoDB client ready:",
    Boolean(client)
  );
});

Für Anwendungen, die vor dem Start ihres HTTP-Servers einen Bootstrap-Vorgang durchführen, bietet dies eine einfache Möglichkeit, die Betriebsbereitschaft zu überprüfen.

Eine Laufzeitumgebung, die anzeigt, was bereits initialisiert wurde

Die AmbitenRuntime bleibt nach dem Bootstrap der wichtigste Vertrag gegenüber der Laufzeitumgebung. Eine typische Anwendung kann Ambiten einmal initialisieren: 

const runtime = await run();

sowie auf folgende Funktionen zugreifen, wie zum Beispiel:

runtime.getMongoClient();
runtime.getModel();
runtime.getSchema();
runtime.getLogger();
runtime.getGraphQL();
runtime.getGCRunner();

neben den Laufzeitvorgängen, darunter:

runtime.registerMultiTenancy(...);
runtime.cache(...);
runtime.invalidateCache(...);
runtime.onConnect(...);
runtime.shutdown();

Diese Unterscheidung ist beabsichtigt:

Bootstrap richtet die Umgebung ein und konfiguriert sie.
Die Laufzeitumgebung stellt die initialisierte Umgebung bereit und betreibt sie.

Durch die Trennung dieser Verantwortungsbereiche bleibt der Anwendungscode relativ klein, auch wenn die Anforderungen an die Infrastruktur steigen.

Warum diese Änderungen von Bedeutung sind

Ambiten wird für Anwendungen entwickelt, bei denen der Zugriff auf MongoDB letztendlich nur noch einen Teil eines größeren Laufzeitproblems darstellt.

Mit zunehmender Komplexität der Systeme müssen sich Entwickler mit folgenden Aspekten auseinandersetzen: Tenant-Identität, Anforderungskontext, Transaktionskontinuität, Laufzeitlebenszyklus, Verbindungsmanagement, Protokollierung, Caching, Validierung, Beobachtbarkeit sowie Adapterintegration.

Das Ziel von Ambiten besteht darin, diesen Aspekten eine gemeinsame Laufzeitgrundlage zu bieten, anstatt dass jede Anwendungsschicht diese unabhängig voneinander koordinieren muss.

Die Stärkung der Beziehung zwischen Schema und Modell in Version 1.2.0 ist Teil dieser Ausrichtung. Ein Schema sollte nicht einfach nur deshalb existieren, weil es beim Start registriert wurde. Ein Modell, das zu diesem Schema gehört, sollte sich bei der Verarbeitung von Dokumenten darauf verlassen können.

Ebenso sollte ein Laufzeit-Verbindungs-Hook den tatsächlichen Zustand der Laufzeit widerspiegeln, anstatt von der Anwendung zu verlangen, dass sie selbst ermittelt, wann die Initialisierung stattgefunden hat. Dies sind die Arten von Garantien, auf denen v1.2.0 weiterhin aufbaut.

Erste Schritte mit Ambiten v1.2.0

Ambiten kann über npm installiert werden:

npm install @ambiten/core

Die Dokumentation ist verfügbar unter docs.ambiten.dev.

Die Dokumentation behandelt die Laufzeitumgebung, die Kontextweitergabe, die Mehrmandantenfähigkeit, Transaktionen, Adapter sowie weitere Komponenten des Ambiten-Ökosystems.

Zudem ist eine neue Tutorial-Reihe in Arbeit, die mit der Erstellung einer auf Ambiten basierenden API beginnt und schrittweise auf die dahinterliegenden Laufzeitkonzepte eingeht. Das Ziel besteht nicht nur darin, zu zeigen, welche APIs verfügbar sind, sondern auch zu erläutern, warum die Laufzeitumgebung existiert und wie ihre verschiedenen Komponenten zusammenwirken.

Der Weg in die Zukunft

Ambiten v1.2.0 ist ein weiterer Schritt hin zu einer konsistenteren Laufzeitumgebung, von der Initialisierung bis hin zur Persistenz.

Schemas stehen nun in einer engeren Beziehung zu den Modellen, die sie nutzen. Die Dokumentvalidierung erfolgt näher an der Laufzeitgrenze, wo sie hingehört. Das Verhalten des Verbindungslebenszyklus ist vorhersehbarer. Und die Bootstrap-Factory reduziert weiterhin den Umfang an Infrastrukturcode, den Entwickler selbst koordinieren müssen.

Es gibt noch viel mehr zu entdecken. In den kommenden Tutorials werden wir uns eingehender mit der kontextbezogenen Laufzeitumgebung von Ambiten, der Multi-Tenancy, Transaktionen, Adaptern und dem Bootstrap-Workflow befassen.

Vorerst stärkt die Version 1.2.0 die Grundlage, auf der diese Funktionen aufbauen.
